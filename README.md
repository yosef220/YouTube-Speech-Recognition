# 🎤 HumFinder — מצא שיר בזמזום / בשירה / במילים

לחצו על כפתור אחד, **אמרו · שירו · או זמזמו** קטע משיר — וההתאמה תיפתח לכם
**ישירות ביוטיוב** בכתובת `youtube.com/watch?v=…` המדויקת.

בדומה לחיפוש-בזמזום של YouTube ולשazam — אבל **בעלות 0 ש"ח**, קוד פתוח, ובלי
תלות בשירות בתשלום.

---

## מה עובד חינם, ומה דורש בנייה עצמית (בכנות)

| יכולת | חינם? | איך |
| --- | --- | --- |
| זיהוי **מילים** שאומרים | ✅ לגמרי | Web Speech API בדפדפן — בלי מפתח |
| זיהוי **שירה עם מילים** | ✅ לגמרי | שירה = טקסט → צבירה רציפה + התאמה מטושטשת למילות השיר |
| **קישור יוטיוב מדויק** מטקסט | ✅ | Piped/Invidious (ללא מפתח) או YouTube Data API (מכסה חינמית) |
| **אימות מול מילות שיר** | ✅ | LRCLIB — חינם, בלי מפתח |
| זיהוי **זמזום** (מנגינה בלי מילים) | ⚠️ בונים לבד | אין שירות ציבורי חינמי — מנוע עצמאי בתיקיית `server/` |

**למה מיקרופון + Shazam ≠ זיהוי שירה.** בדקנו את תוסף Shazam הרשמי (v2.5.0): הוא לוכד
את **אודיו הלשונית** דרך `chrome.tabCapture`, מייצר טביעת אצבע קונסטלציה ב-`sigx.wasm`
הקנייני, ושולח ל-`shazam.com/services/webrec/match_extensionv2`. טביעת האצבע מזהה
**הקלטה מסוימת** — פסגות ספקטרליות מהטמבר, התופים והמיקס של המקור. כשאתה **שר**
a cappella הפסגות האלה פשוט לא קיימות, ולכן Shazam מחזיר אפס. גם החלפת `tabCapture`
ב-`getUserMedia` (מיקרופון) לא תעזור — זה עדיין אותו אלגוריתם הלא-נכון לקול אנושי.

**המסקנה שמנחה את הפרויקט:** "משתמש ששר" הוא דווקא המקרה הקל, כי כשמישהו שר יש
**מילים**, ומילים זה **טקסט**. לכן הפרויקט בנוי בשכבות: מילים/שירה שעובדות מיד וחינם,
ומנוע זמזום (מנגינה בלי מילים) שאתם בונים ממאגר קטן ואישי משלכם.

```
YouTube-Speech-Recognition/
├── web/
│   └── index.html      ← שלב 1: פרונטאנד סטטי (מילים · שירה · זמזום). עובד מיד.
├── server/
│   ├── app.py          ← FastAPI: POST /hum → {videoId, title, score}

│   └── requirements.txt
├── build_db/
│   ├── ingest.py       ← yt-dlp → (Demucs) → CREPE → contour → db/

└── db/                 ← נוצר על ידי ingest.py (לא נשמר ב-git)
```

## שלב 1 — מצב "מילים": עובד היום, בלי שרת

```bash
cd web
python3 -m http.server 8000
# פתחו http://localhost:8000
```

מיקרופון דורש `https` או `localhost`. זיהוי הדיבור עובד ב-Chrome / Edge.

שלושה מצבים בכפתור אחד:

- **מילים** — משפט אחד ברור. דיבור→טקסט → הצלבה מול LRCLIB → חיפוש יוטיוב → פתיחת הסרטון המדויק.
- **שירה** — כוונון לשירה, לא לדיבור: `continuous=true` עם **צבירת כל המילים** לאורך
  חלון של 15 שניות (שירה מגיעה בפרצים עם הפסקות בין שורות — לא נחתך בשקט הראשון),
  ואז **התאמה מטושטשת**: מנקדים כל שיר לפי כמה מהמילים שנקלטו מופיעות במילותיו
  (LRCLIB), עם סובלנות לטעות אות אחת. מספיק ש-3–4 מילים ייצאו נכון. תמלול מלוכלך
  כמו "אני הולך אותך" עדיין ננעל על "אני אוהב אותך".
- **זמזום** — מנגינה בלי מילים; שולח לשרת ההתאמה משלב 2 (ראו למטה).

תחת ⚙️ אפשר להזין מפתח YouTube Data API חינמי ליציבות (~100 חיפושים/יום).

### אירוח חינמי — GitHub Pages (מובנה)
בריפו כבר יש `.github/workflows/pages.yml` שמפרסם את `web/` אוטומטית:

1. ב-GitHub: **Settings → Pages → Source: GitHub Actions** (חד-פעמי).
2. כל דחיפה ל**ברירת-המחדל של ה-repo** מפרסמת אוטומטית. שימו לב: סביבת
   `github-pages` מרשה לפרוס **רק מברנץ ברירת המחדל**, ולכן ה-workflow מכוון אליו
   (`claude/humming-song-search-ace9y4`). כדי לפרסם מ-`main`: הפכו אותו לברירת
   המחדל (**Settings → General → Default branch**) ואז שנו את ה-`branches` ב-workflow ל-`[main]`.
3. הכתובת תופיע ב-**Actions → Deploy web/ to GitHub Pages** — בדרך כלל
   `https://<user>.github.io/<repo>/`. כולל `https`, שנדרש למיקרופון.

לחלופין: Cloudflare Pages / Netlify — הצביעו על תיקיית `web/`, בלי שלב build.

## שלב 2 — מנוע הזמזום העצמאי

הרעיון שפותר את "הקישור המדויק": **בונים את מסד המנגינות מיוטיוב עצמו**, כך שכל
רשומה כבר נושאת את ה-`videoId` שלה — ההתאמה מחזירה קישור מדויק בהגדרה.

### א. בניית המסד (רץ פעם אחת, אופליין)

```bash
cd build_db
# ערכו את playlist.txt — כתובת יוטיוב אחת בכל שורה
pip install yt-dlp demucs librosa soundfile numpy torch torchcrepe
python ingest.py --playlist playlist.txt --out ../db
#   --no-demucs   לדלג על הפרדת שירה (מהיר יותר, פחות מדויק)
#   --keep-audio  לא למחוק את קבצי ה-WAV שהורדו
```

לכל שיר: `yt-dlp` מוריד אודיו → Demucs מבודד את השירה → CREPE מחלץ עקומת פיץ'
→ נרמול לחצי-טונים עם החסרת חציון (אי-תלות בסולם) → נשמר ב-`db/`.

### ב. הפעלת שרת ההתאמה — מקומית

```bash
cd server
pip install -r requirements.txt
uvicorn app:app --port 8000
```

בפרונטאנד, תחת ⚙️, ודאו שכתובת "שרת הזמזום" מצביעה לשרת (ברירת מחדל
`http://localhost:8000`). עכשיו מצב **זמזום** יקליט 8–12 שניות, ישלח ל-`POST /hum`,
ויציג את ההתאמות המובילות עם קישורי היוטיוב המדויקים.

### ג. פריסה חינם ל-Hugging Face Space (Docker)

תיקיית `server/` היא Space מוכן לפריסה (Dockerfile + `README.md` עם frontmatter).
בטייר ה-CPU החינמי לא מותקן torch — `melody.py` נופל אוטומטית ל-`librosa.pyin`,
כך שהאימג' קטן והעלייה מהירה.

1. צרו Space חדש → **SDK: Docker** → **Hardware: CPU basic (free)**.
2. דחפו את תוכן `server/` ל-repo של ה-Space:
   ```bash
   git clone https://huggingface.co/spaces/<user>/<space> hf-space
   cp server/* server/.dockerignore hf-space/
   cd hf-space && git add -A && git commit -m "HumFinder server" && git push
   ```
   ה-Space יבנה ויעלה בכתובת `https://<user>-<space>.hf.space` (כתובת **https**,
   ולכן אתר ה-GitHub Pages יכול לקרוא לה בלי חסימת mixed-content).
3. בעמוד, תחת ⚙️, הזינו את כתובת ה-`hf.space` בשדה "שרת הזמזום". אפשר גם להטמיע
   אותה בקישור: `…github.io/<repo>/?server=https://<user>-<space>.hf.space`.

`POST /hum` יחזיר **503** עד שיהיה מסד. בנו אותו מקומית (שלב א') והוסיפו את
`db/melodies.npy` + `db/meta.json` ל-repo של ה-Space, או העלו אותם ל-`/app/db`
דרך אחסון קבוע. פרטים נוספים ב-[`server/README.md`](server/README.md).

### למה זה מדויק
- **subsequence-DTW** (ולא DTW רגיל): מזמזמים קטע מאמצע השיר, והאלגוריתם מאתר את
  החלון המתאים ביותר בתוך השיר המלא.
- **החסרת חציון**: מזמזמים בסולם אקראי; אחרי החסרת החציון נשארים רק המרווחים בין
  הצלילים — וזה מה שמזהה מנגינה.
- **CREPE עם נפילה ל-pyin**: איכות פיץ' גבוהה אם `torchcrepe` מותקן, אחרת
  `librosa.pyin` — עדיין עובד בלי GPU.

### ציפיות דיוק (top-5)
| תרחיש | הצלחה משוערת |
| --- | --- |
| אמירת משפט ברור, שיר מוכר | 85–95% |
| שירה עם מילים | 70–85% |
| זמזום, מסד אישי של ~500 שירים | 60–80% |
| זמזום, מסד ענק (50K+) | 30–45% |

**מסקנה:** מסד קטן ואישי עדיף על ענק. טענו 300–800 שירים שאתם באמת מחפשים.
